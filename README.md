# Compare AI meeting

Инструкции для ИИ-агентов: `AGENTS.md`, Claude Code читает его через
мост `CLAUDE.md`. Здесь описание для человека.

Стенд для сравнения моделей на одной задаче: превратить стенограмму
встречи в протокол по фиксированному промпту и посмотреть, кто справился
лучше. Прогоняет один и тот же текст через несколько моделей OpenRouter
и локальную Ollama, складывает ответы рядом и считает стоимость.

## Что публикуется, а что нет

Публикуется код и промпт. Данные встреч наружу не уходят — это рабочие
стенограммы с именами участников и коммерческими показателями
(`RULES.md` аудитора, п.15: код рабочих проектов публикуется целиком,
данные нет).

В `.gitignore` и потому отсутствуют в репозитории:

- `Meeting/` — сырые стенограммы. Кладутся туда руками.
- `results/` — всё, что нагенерили модели: протоколы, summary, сравнения,
  `runs.json`.
- `.env` — ключ OpenRouter.

Каталоги нужно создать на своей машине, программа сама их не заводит,
кроме `results/`.

## Как запустить

```
python compare.py --transcript "Meeting/имя-файла.txt"
```

Ключ ищется в `.env` рядом с `compare.py` (`OPENROUTER_API_KEY=...`) или
в переменных окружения. Без ключа работают только локальные модели Ollama.

Список моделей и флаг `enabled` для каждой — в начале `compare.py`,
секция `MODELS`. Промпты, по которым строится протокол, —
`Promt/System promt.md` (системный) и `Promt/User promt.md` (шаблон
сообщения с полями `[Date]`, `[Users]`, `[Transcription]`).
`Promt/System promt 5.6.md` - системный промпт, переписанный под
GPT-5.6 luna.

В `redteam/` лежит синтетическая стенограмма с вшитыми попытками
инъекции и порядок проверки: стенограмма это недоверенный вход, и
устойчивость моделей к нему проверяется отдельно от качества протокола.
Реальных данных там нет, каталог публикуется.

Результат одного прогона: `results/<имя встречи>/` — по файлу на модель в
`raw/`, сводка в `results.md`, метрики и стоимость в `runs.json`.
