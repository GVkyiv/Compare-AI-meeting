# Спецификация: Интеграция MLflow в Compare AI meeting

Дата: 20.10.2026
Статус: Согласовано (по результатам сессии grilling)

## 1. Контекст и цели

Стенд `Compare AI meeting` предназначен для сравнения качества работы различных LLM и вариантов промптов при составлении протоколов встреч по стенограммам.

Цель интеграции:
Обеспечить структурированное хранение истории экспериментов, сравнение запусков моделей по ключевым метрикам (токены, стоимость, время, корректность структуры протокола) и визуализацию через интерфейс MLflow UI без ущерба для приватности корпоративных данных и слепой оценки качества.

## 2. Архитектурные решения

1. **Зависимости:**
   MLflow оформляется как зависимость проекта через файл `requirements.txt`.
2. **Флаг отключения:**
   Добавляется параметр CLI `--no-mlflow`, позволяющий выполнять тестовые и сухие запуски без обращения к трекеру.
3. **Хранилище:**
   Локальный каталог `./mlruns` рядом со скриптом `compare.py`. Отслеживание через URI `file://.../mlruns`.
4. **Приватность данных:**
   Каталог `mlruns/`, базы данных `*.db` и служебные файлы трекера строго изолируются от git через `.gitignore`. Репозиторий остается публичным, артефакты и стенограммы наружу не попадают.
5. **Слепая оценка (Blind evaluation):**
   MLflow логирует реальные имена моделей (`gpt-5.6-luna`, `qwen3.8-27b` и др.) для инженерного анализа. В регламент проекта вносится явное правило: пользователь обязан сначала провести слепую оценку по файлу `for_opus.md`, и лишь после этого открывать MLflow UI.
6. **Режим пересборки (`--rebuild`):**
   При запуске с флагом `--rebuild` данные берутся из локального `runs.json`, новые runs в MLflow не создаются.

## 3. Структура эксперимента и запусков

- **Эксперимент:** `meeting-protocol-eval`.
- **Родительский run (Parent Run):**
  - Имя: `{transcript_stem}_{YYYYMMDD_HHMMSS}`
  - Параметры:
    - `transcript_name`: имя файла стенограммы
    - `transcript_stem`: идентификатор встречи
    - `transcript_chars`: длина стенограммы в символах
    - `transcript_estimated_tokens`: оценка объема токенов
    - `date_arg`: переданное значение даты
    - `users_arg`: переданный список участников
    - `models_count`: число участвующих моделей
    - `temperature`: температура генерации
  - Метрики:
    - `total_cost_usd`: суммарная стоимость сессии в долларах
    - `successful_models`: число успешно ответивших моделей
    - `failed_models`: число упавших моделей
  - Артефакты:
    - `results.md`
    - `for_opus.md`
    - `key.md`
    - `runs.json`
- **Дочерние запуски (Nested Child Runs):**
  - Создаются внутри контекста родительского run для каждой модели.
  - Имя: `{model_label}` (например, `gpt-5.6-luna`)
  - Параметры:
    - `model_id`: идентификатор модели в API
    - `model_kind`: тип провайдера (`openrouter` или `ollama`)
    - `temperature`: температура
    - `blind_label`: анонимная метка в текущем прогоне (А, Б, В...)
  - Метрики:
    - `prompt_tokens`: число входных токенов
    - `completion_tokens`: число выходных токенов
    - `total_tokens`: общее число токенов
    - `cost_usd`: стоимость вызова
    - `seconds`: время ответа модели в секундах
    - `protocol_chars`: длина сформированного протокола в символах
    - `sections_found`: количество найденных обязательных секций (из 8)
    - `sections_total`: норматив количества секций (8)
    - `sections_order_valid`: флаг корректности порядка секций (1.0 или 0.0)
    - `utochnyty_count`: количество маркеров «Уточнити»
    - `dates_count`: количество распознанных дат
    - `tables_count`: количество таблиц
    - `truncated`: флаг обрезки по длине контекста (1.0 или 0.0)
  - Теги:
    - `status`: `success` или `failed`
  - Артефакты:
    - Файл сгенерированного протокола `{model_label}.md`

## 4. План реализации

1. Внести `mlruns/`, `mlruns.db`, `*.db`, `.trash/` в `.gitignore`.
2. Создать `requirements.txt` (`mlflow>=3.0.0`).
3. Установить зависимости в рабочее окружение.
4. Доработать `compare.py`: подключить mlflow, объявить флаг `--no-mlflow`, обернуть вызовы моделей в вложенные runs, залогировать параметры, метрики и артефакты.
5. Обновить `AGENTS.md`, `README.md` и `agent-checks.md`.
6. Прогнать контрольные проверки синтаксиса и сухой запуск.
