# Compare AI meeting

Стенд сравнения моделей на задаче: превратить стенограмму встречи в
протокол. Предмет проекта не сам протокол, а выбор пары «модель +
промпт»: разным моделям нужны разные промпты при одинаковом входе.

## Текущее решение

17.09.2026 для продуктового сервера выбрана GPT-5.6 luna с промптом R3:
`Promt/System promt 5.6.md`, коммит `3bdd9ae`, шаблон `Promt/User promt.md`
без изменений (ранее GPT-4.1 mini). Основание: три встречи (разборы в
`eval/round-00.md` ... `eval/round-03.md` и `eval/holdout-03.md`). R3
лучше mini по выдумкам, пропускам и срокам. Процесс шёл итерациями по
промпту, а не через спеку по п.13: это пропуск, а не отказ.

Проект корпоративный. Данные рабочие, граница «код наружу, данные нет»
обязательна, см. раздел «Публикация».

## Файлы

- `compare.py`: стенд одним файлом. Список кандидатов в константе
  `MODELS` (`label`, `kind`, `id`, `enabled`).
- `Promt/System promt.md` и `Promt/User promt.md`: промпты с сервера (n8n
  + Webex). В шаблоне подставляются `[Date]` и `[Users]`. Ожидаемая
  структура из 8 секций зашита в `SECTION_TITLES` в `compare.py`.
- `eval/`: слепая оценка выходов: стенограмма, `A.txt`, `B.txt`, ключ в
  `eval/key.md` (агенту не открывать). Устройство в `eval/README.md`.
- `Meeting/`: сырые стенограммы (вне git).
- `results/<имя>/`: результаты прогона (вне git).
- `.env`: ключ OpenRouter (вне git). Доступ агента закрыт в
  `.claude/settings.json`.
- `redteam/`: стенд проверки устойчивости к инъекциям (без реальных данных).
- `agent-checks.md`: контрольные задания для поведенческой проверки агентов.
- `docs/quality-eval.md`: методология оценки качества.
- `README.md`: описание проекта без внутренних деталей.

## Как запускать

```
python compare.py --transcript "Meeting/имя-файла.txt"
```

- `--models`: список меток через запятую.
- `--list`: показать кандидатов и выйти.
- `--rebuild`: пересобрать отчёт из `runs.json` без API (пробовать первым).

Ключ ищется в `.env` рядом со скриптом (`OPENROUTER_API_KEY`,
`OPEN_ROUTER_API`) или в переменных окружения.

## Как читать результат

Прогон кладёт в `results/<имя>/`: `raw/<label>.md`, `results.md`,
`for_opus.md` (обезличенные «Модель А, Б»), `key.md`, `runs.json`.

**Порядок чтения обязателен: сначала `for_opus.md`, потом `key.md`.**
Перемешивание защищает от предвзятости. Открыть `key.md` или `results.md`
первым значит испортить слепое сравнение.

## Как меряется качество

Задача: оценка субъективного качества (RULES.md, п.18.1 Align Evals).
`check_protocol` меряет форму, а не факты. Слепое сравнение в
`write_outputs` реализует первую часть п.18.1; размеченная выборка и судья
описаны в `docs/quality-eval.md`.

## Инъекции в стенограмме

Стенограмма - недоверенный вход от третьих лиц (RULES.md, п.16).
Летальная триада: приватные данные есть, недоверенный вход есть, отправка
в OpenRouter есть.
**Защита:** у модели нет инструментов (tools). Она возвращает текст,
скрипт пишет его в файл. Ни выполнения кода, ни сетевых запросов по воле
модели нет. Риск инъекции - порча протокола и искажение сравнения.
Архитектура: разделение ролей (`system` отдельно, стенограмма в `user`),
человек в контуре. Стенд проверки: `redteam/` (на 25.09.2026 прогон в
процессе актуализации под новый промпт).

## Тесты / проверка

Автотесты логики (`pytest`) - технический долг (кандидаты:
`check_protocol`, `estimate_tokens`, `calc_cost`).
Проверка для агента после правок кода:
1. Синтаксис: `python -m py_compile compare.py`
2. Сухой прогон: `python compare.py --list`
3. Контрольные задания: `agent-checks.md`.

## Язык

Протокол на выходе украинский (требование промпта). Документация и
диалог на русском. Без тире, только дефис, запятая, двоеточие.
